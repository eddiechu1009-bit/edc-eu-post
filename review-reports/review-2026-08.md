## 🔴 重大發現 #1：`build.py` 缺 `tag-money` 對應，分類靜默遺失

**症狀**：30 天內 90 則文章有 **9 則 `tags` 為空**，前端分類篩選抓不到這些文章。

**根因**：日報 HTML 使用 `<span class="tag tag-money">貨幣</span>` 標記匯率／貨幣類新聞，但 `eu-intel-site/build.py:76-83` 的 `TAG_MAP` 只定義六類，**沒有 `tag-money`**：

```python
TAG_MAP = {
    'tag-tax': '稅務',      'tag-compliance': '合規',
    'tag-macro': '總經',    'tag-platform': '平台',
    'tag-logistics': '物流', 'tag-trade': '貿易',
}   # ← 缺 'tag-money': '貨幣'
```

`build.py:139-141` 逐一比對 CSS class，比不到就留空陣列，**不會報錯也不會警告**——所以這個問題已靜默存在一段時間。

**影響範圍**（已用 grep 核實）：

- 全站日報原檔共 **11 處** `tag-money`，其中 **10 處落在 7 月～8 月**（7/13、7/16、7/20~7/24、7/30、7/31 等 20 個檔案）
- 30 天窗內受影響 **9 則**，全部是 ECB／Fed／BoE 決策與 EUR/USD 匯率文章——正好是站點的高價值總經內容
- 這也連帶讓上月報告的分類佔比失真（上月「30 天 70 則」的分類加總同樣不足）

**修法**：在 `TAG_MAP` 補一行 `'tag-money': '貨幣'`，重跑 `python eu-intel-site/build.py`，並確認 `index.html` 的分類篩選器有「貨幣」選項（若沿用 tags 動態生成則自動出現）。

> 這與記憶中「Seller Intel BR 欄位必須動態對應、寫死會爆錯」是同一類問題：**寫死的對應表與上游產出脫節，且失敗時靜默**。建議在 `build.py` 加一道警告：解析完若有文章 `tags` 為空，印出日期＋標題，比照現有的「內部詞警告」機制（`build.py:341-345`）。
